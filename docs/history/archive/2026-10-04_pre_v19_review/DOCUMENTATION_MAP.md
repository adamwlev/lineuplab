## Maintenance rules

1. Change the owning current page, not every document that once mentioned a
   result. Keep the root README stable; it is a map, not a journal.
2. Replace the current handoff with one dated checkpoint. Archive the displaced
   record before losing useful history. Keep archive paths explicitly historical.
3. At a completed research milestone, update state, scorecard and backlog in
   their separate roles. Keep the architecture page aligned with implemented
   code; label proposals as proposals.
4. Preserve frozen plans, completed artifacts and original reports. Corrections
   go into a new dated analysis with a clear supersession link from current
   guidance, not a rewritten experiment.
5. Every “best” claim needs a population, information set, metric, date and
   uncertainty qualification. Every “closed” conclusion needs its tested scope.
6. Use working Markdown links in current guidance; verify targets/anchors,
   exact commands and receipt-backed statuses. Historical links inside exact
   snapshots are a documented exception, not a reason to rewrite them.
7. Long-run commands live with current operations or the relevant launch
   checkpoint. Do not duplicate runnable stale launch instructions into
   README/CLAUDE. A written plan never implies a run was launched.
