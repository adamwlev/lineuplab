# Refactor plan (started 2026-10-09)

## Why

Research code grew to 609 modules in `experiments/`. The v20 runner alone
imports 186 of them (2 MB). The retained model is assembled through an
inheritance chain from v3 to v20 and trained in three stages per origin:

1. the v14 offense;
2. the v15 defense adapter on the frozen offense;
3. the v16 joint fit.

Each campaign added versioned copies instead of changing shared code, because
completed runs fingerprinted their sources. The result is slow to change and
hard to reason about. The exact old code is preserved at tag
`pre-refactor-2026-10-09`. Nothing in this refactor needs it to stay in the
working tree.

## Target

A small package, `lineups/`, with one implementation of each idea:

| Module | Responsibility |
| --- | --- |
| `lineups.db`, `lineups.paths` | Database connection from the environment or `~/.pgpass`; artifact locations |
| `lineups.data` | Possession and event tables; game × offense-five × defense-five aggregates with event labels |
| `lineups.features` | Dated player states (offense, role, rebound, defense), adjusted capability banks, normalizers |
| `lineups.model` | The event model as flat modules (teammate context, defense, constraints, rebound renewal, ledger), with no version inheritance |
| `lineups.train` | Rolling-origin fitting: inner selection, final refit and checkpoint averaging |
| `lineups.baselines` | Additive and additive_defense controls |
| `lineups.evaluate` | Cohorts, prior-only calibration, blends, metrics, season-block contrasts |
| `lineups.coherence` | Fixtures and the directional property suite |
| `lineups.uncertainty` | Finite-game bands, persistent discrepancy, structural disagreement |
| `lineups.legacy` | Readers for pre-refactor artifacts: saved fits, cached inputs, scored cells |

The package will have new tests under `tests/`. Commands run as
`python -m lineups.<module>`.

## Parity ladder

Each rung must pass before the next layer is trusted. "Exact" means float64
agreement to about 1e-9 on the same inputs. "Statistical" means within the
spread across seeds, on whole origins.

1. **Inference.** A flat model loads saved J_POINT_BOTH weights and reproduces
   saved native predictions exactly.
2. **Evaluation.** New calibration, blending and metrics reproduce the
   scorecard rows from saved native predictions exactly.
3. **Inputs.** New feature builders reproduce cached batch inputs exactly at
   sampled origins and dates.
4. **Training.** One clean training path, with no frozen-parent staging if
   possible, matches the reference statistically on a few origins. This is a
   bounded run under six hours, and the result decides whether the three-stage
   procedure is needed.
5. **Upstream.** The adjusted-bank GLM library reproduces cached snapshots at
   sampled dates. A full rebuild is only needed for new data (2026–27).

## Retirement

Once rungs 1–3 pass, the research path no longer needs `experiments/`. The old
modules and their tests then leave the working tree; the tag keeps them.
Readers for old artifacts move into `lineups.legacy`. Untracked caches stay on
disk until Adam approves a cleanup.

## Rung 5 plan (2026-10-09)

**Why now.** Two pieces of work need it:

- **The 2026–27 prospective test.** It needs states, library snapshots,
  normalizers and controls for new origins.
- **The 2009–2013 backtest.** It is the only data source with real support
  for big lineups.

The legacy builders hard-code the 2014–2026 schedule and origin indices 0–51,
so extending them in place is impractical. Port them into `lineups/`,
parameterized by season range, and verify them on 2014–2026 before
extending.

| Step | Legacy source (tag `pre-refactor-2026-10-09`) | Output in the store | Verification |
| --- | --- | --- | --- |
| Schedule (**done**, `lineups/schedule.py`) | `asof_point_benchmark.build_schedule` | quarter windows for any season range | rows equal `asof_points_2026/schedule.csv` |
| Player states (**done**, `lineups/states.py`, from the cached v3 `game_lineups.npz`) | `joint_capability_data` + `joint_capability_v3_data` (EB 180/730-day states, role contrasts) | `offense_games`, `offense_origins` | bit-identical arrays (48 s) |
| Rebound states (**done**, `states.rebound_sweep`) | `joint_capability_v14_data.build_states` | `rb_prob`, `rb_neff`, `league` | bit-identical |
| Defense descriptors (**done**, `states.defense_sweep`) | `joint_capability_v15_data` | `defense_games`, `defense_origins` | bit-identical |
| Capability library | `joint_capability_v16_library` + `solver`, `profiles`, `location_*`, `curvature`, `draws` | `library_offense`, `library_defense` | sampled snapshots within solver tolerance |
| Normalizers and environment (**done**, `lineups/normalizers.py`) | v3/v8/v14/v16 moment and environment code | `normalizers/`, `environment.json` | equal to 1e-9 at three origin-phases |
| Loss references (**done**, `lineups.train.references`) | `v16_fit.references` | `references.json` | 1e-13 at 2015q1 inner; for two-phase fits, use the phase-B starting model |
| Additive controls (**scoring done**, `lineups/additive.py`; the ridge fit still runs from the old code through `scripts/additive_origin_fit.py`) | `asof_additive_tuning.fit_origin` (fit); `asof_point_calibration`, `onfloor_defense`, `asof_additive_reference`, `joint_capability_v15_controls`, `joint_capability_v16_controls` (scoring, centering, calibrations) | additive_defense for any fives at an origin | per-row additive_defense equal to 5e-13 at 2015q1, 2016q1, 2020q3 and 2026q4; calibration histories are the saved 2015–2026 cells |

**Order.** Schedule and player states come first. They are deterministic,
verifiable, and enough to begin extending origins back. The library comes
last; it is the largest and slowest piece.

**Normalizers: what actually reaches the model.** Only these keys of a store
normalizer enter a batch:

- `cutoff_day`;
- `base_mean` and `base_sd`, from v9 `origin_shared` → `state_moments`, with
  v9 `arm_weights` row weights;
- `role_mean` and `role_scale`, the moments of x[..., 55:63] from v9
  `standardization_and_reference`;
- `rebound_mean` and `rebound_scale`, from v14 `extend_shared`;
- `defense_mean` and `defense_scale`, from v16 `make_shared`, with weights of
  possessions × 2^(−age/730);
- `offense_*` and `defense_bank_*`, from v16 `fit_normalizers`.

The environment needs three numbers: `budget` (v3 `usage_budget`), `eta` and
`non_rebound` (v14 `environment`). Team baselines and v12 additive offsets
feed only the legacy readout offset, which the forward pass ignores, so the
port can skip them. Loss references must be redefined for two-phase fits.
